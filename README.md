# מנטור מעבדה לפיזיקה

מערכת הדרכה למעבדת פיזיקה: מנטור AI שמלווה תלמידים בעמדת ניסוי (עמדה 1: מנוע תלת־פאזי עם וסת תדר), ומסך מורה לשיעור חי.
המאגר מרכז את מסמכי האפיון והעיצוב שהופקו לפרויקט. עדיין אין בו קוד.

## מצב הפיתוח

- **שלב 1 · מסך תלמיד:** תרגיל EX-01 מקצה לקצה על ההקלטות הסינתטיות: רקע ושאלת הבנה, תחזית, צפייה עד נקודת העצירה, השערה, איסוף ראיות מהגרף, נימוק עם אבחון, בדיקה חוזרת ושאלת יציאה. EX-02 עד EX-04 נטענים, והתוכן שלהם עדיין טיוטה.
- **שלב 2 · מסך מורה:** שיעור עם קוד הצטרפות, כרטיסי עמדות לפי דחיפות, התראות עם הצעת התערבות, השהיה, רמז והודעה לעמדה, יומן עמדה ומחוון מוצע.
- **שלב 3 · Claude כמנטור:** Claude מנסח רמזים ומשוב, ועונה על שאלה חופשית של התלמיד. מודל מהיר מסווג טקסט חופשי בשביל המורה. כל ניסוח עובר מאמת: עד שני משפטים, מסתיים בשאלה, בלי מונחים שחושפים את התשובה, רק מספרים שהתלמיד ראה, בלי הוראה פיזית. אם הניסוח נכשל במאמת, יש ניסיון חוזר אחד ואחריו המערכת חוזרת לטקסט המאושר. Claude לא מחליט אם התלמיד צודק. **בלי מפתח API המערכת עובדת עם הטקסטים המאושרים בלבד.**

**הפעלת Claude:** מגדירים משתנה סביבה `ANTHROPIC_API_KEY` לפני הפעלת השרת. המודלים: `claude-opus-5-5` לניסוח ו־`claude-haiku-5-5` לסיווג. אפשר להחליף אותם ב־`LLM_MODEL_PHRASE` וב־`LLM_MODEL_CLASSIFY`. בדיקת עמידות מול ״תלמידים מדומים״ שמנסים לחלץ תשובה: `python3 tools/eval/adversarial.py`.

| תיקייה | תוכן |
|---|---|
| `apps/api/` | שרת Python (FastAPI): ייבוא נתונים, מכונת המצבים, שער הזמן, מנוע האבחון, API |
| `apps/web/` | מסך העמדה (React) |
| `content/` | תוכן התרגילים, קטלוג הערוצים, ומפתח התשובות (`answer_key.yaml`, לשרת בלבד) |

- **שלב 4 · השלמות להדגמה:** תרגיל EX-05 (שתי ההרצות התקינות ברצף), שמירת סשנים ושיעורים לדיסק כך שאתחול השרת לא מוחק שיעור פעיל, סקריפט הפעלה וקובץ Docker.

- **שלב 5 · הכנה לעמדה חיה ולפיילוט:** מעטפת בטיחות לפי מוח 1 (`content/envelope.yaml`, כל הערכים ״מוצע״ עד אישור תלם) עם התראת בטיחות למורה בראש המסך. קליטת נתונים מבקר העמדה בפרוטוקול `obs.v1`: קוד מכשיר, מסגרות שנשלחות שוב לא נקלטות פעמיים, ספירת פערים. סימולטור של בקר העמדה, מסך ניטור ערוצים חי, אישור ציון בידי המורה, וייצוא ציונים ל־CSV.

- **שלב 6 · כניסת מורים:** חשבון לכל מורה, סיסמה שנשמרת רק כגיבוב (PBKDF2 עם מלח), עוגיית כניסה חתומה לתוקף 12 שעות, נעילה ל־5 דקות אחרי 5 ניסיונות שגויים. כל מורה רואה רק את השיעורים שלו. תלמידים לא צריכים כניסה: הם מצטרפים עם קוד השיעור. התלמיד רואה רק את מספר התרגיל, והמורה רואה גם את שמו.

- **שלב 7 · הכנת שיעור:** אשף בחמישה צעדים לפי מסמך ה־UX: כיתה ועמדות, תרגיל, תצוגה מקדימה של מה שהתלמידים יראו (והמפתח, למורה בלבד), הגדרה ובטיחות, עזרה וציון. ההגדרות עוברות לכל עמדה שמצטרפת: מכסת רמזים (0 עד 3), שאלה פתוחה או כפתור רמז בלבד, וניכוי של נקודה לכל רמז שהתלמיד ביקש. אפשר לפתוח את השיעור מיד או לשמור אותו כמתוכנן: עמדות לא יכולות להצטרף לשיעור מתוכנן עד שהמורה פותחת אותו. וריאציות לכל עמדה ואשף הגדרה פיזי ייכנסו עם העמדה החיה.

  **הגדרות העמדה לכל תרגיל** (`content/setup.yaml`): מצב ההתחלה של כל רכיב בעמדה (וסת, בלם, מנוע, מנתחים, בקר), שנגזר מהשניות הראשונות של כל הקלטה, וקריאות צפויות לבדיקה לפני ההתחלה. מה שמשתנה במהלך ההרצה (מתי, באיזה רכיב, בעמדה או בתוכנה) נמצא ב־`answer_key.yaml` תחת `scenario`, ומוצג למורה בלבד. המערכת בודקת כל הקלטה מול מעטפת הבטיחות: תרגיל 4 עובר את המומנט והזרם הנקובים, ולכן מסומן ״לא לשחזר בעמדה חיה״.

- **שלב 8 · כיתה לאורך זמן:** לשונית ״כיתה״ עם בחירת כיתה ותקופה (שבוע, חודש, 3 חודשים, הכול): מפת מחוון של קבוצה מול היבט, תפיסות שגויות נפוצות עם מגמה משיעור לשיעור, זמן חציוני בכל שלב וכמה פעמים קבוצות נתקעו, ושליטה בכל כרטיס ידע ברמת כיתה וקבוצה. הכול מחושב מהשיעורים שכבר נשמרו. קבוצות מזוהות לפי השם שהקלידו בהצטרפות; מעקב אחרי תלמיד יחיד ייכנס עם רשימת תלמידי הכיתה. כיתה לדוגמה (ארבעה שיעורים, נתונים מומצאים):

```bash
python3 tools/seed_demo_class.py
```

מוחקים אותה עם `--remove`. אחרי שתי הפקודות מפעילים מחדש את השרת.

- **שלב 9 · תלמידים:** רשימת תלמידים לכל כיתה (לשונית ״תלמידים״: הדבקת שמות, שינוי שם, סימון כלא פעיל). כשלשיעור יש כיתה עם רשימה, הקבוצה מסמנת במסך ההצטרפות מי בה, והמורה יכולה לתקן מתוך יומן העמדה. לכל תלמיד: ממוצע מחוון, מגמה משיעור לשיעור, תפיסות שגויות, שליטה בכרטיסי ידע, ורשימת השיעורים עם מי עבד בכל אחד. ציון התלמיד הוא ציון הקבוצה שלו באותו שיעור.

  **פרטיות:** נשמר שם תצוגה בלבד (מומלץ שם פרטי ואות), בלי מספר זהות או פרטי קשר, בקובץ `rosters.json` שרק השרת קורא. מי שמחזיק קוד של שיעור פתוח רואה את שמות הכיתה במסך ההצטרפות, ולכן כדאי לסגור שיעור בסופו. תלמיד שעזב מסומן כלא פעיל, וההיסטוריה שלו נשמרת.

- **שלב 10 · תוכן:** לשונית ״תוכן״ לעריכה ואישור של התרגילים במסך: טקסטים לתלמיד, שאלת הבנה ותשובות, שלושת הרמזים, מסקנה מצופה ורשימת המילים שחושפות את התשובה. בכל שמירה המערכת בודקת שטקסט לתלמיד לא מכיל מילה מהרשימה (גם בזמן הקלדה), שכל רמז הוא שאלה, ושהתשובה הנכונה היא אחת התשובות. כל שינוי מחזיר את התרגיל לטיוטה עד אישור חוזר, ונרשם בהיסטוריה (מי, מתי, מה). השינויים נשמרים בשרת כשכבה מעל קבצי המאגר (`content_overrides.json`): אפשר לחזור לנוסח המאגר, או לייצא את השינויים ל־YAML ולעדכן את `content/`. הסיבה, הראיות וחלונות הזמן קשורים למנוע האבחון ונשארים בקבצים. שינוי בתרגיל חל מיד גם על שיעורים פתוחים.

**סרטון הדרכה:** `tools/tutorial/make_video.sh` מקליט סרטון של כ־7.5 דקות על המערכת האמיתית, מקצה לקצה, עם עכבר מדומה והסברים בכתב (בלי קריינות). הוא רץ על תיקיית נתונים זמנית ולא נוגע בנתוני המערכת. אחרי שינוי במסכים מריצים אותו שוב.

- **הקשחה ל־MVP (חבילות 1–3):** הנתונים עברו ל־SQLite (`var/state/lab.db`), עם נעילה לכל קבוצה ומזהים של 128 ביט. לשיעור יש מחזור חיים: קוד ייחודי, ״סיום שיעור״, סגירה אוטומטית אחרי `LESSON_HOURS` (ברירת מחדל 4), וקבוצות שעובדות יכולות לסיים. כל קבוצה קשורה לטאבלט שבו הצטרפה (המורה יכולה ״להעביר לטאבלט אחר״). קודים ושמות סיסמה שגויים מוגבלים לפי כתובת, מצב הדגמה נפתח רק עם `DEMO=1`, בקשות מאתר זר נחסמות, וקובץ הציונים לא מריץ נוסחאות.

- **חבילה 5 · נעילת גרסה:** כל קבוצה שומרת עותק של התרגיל ומפתח התשובות שאיתם התחילה, עם מזהה גרסה קצר. עריכת תוכן באמצע שיעור לא משנה קבוצות שכבר עובדות, וציון ניתן תמיד לשחזור. בקובץ הציונים יש עמודה ״גרסת תוכן״.

- **חבילה 4 · בעלות (טננט ← מעבדה ← עמדה):** כל מורה, שיעור, קבוצה ועריכת תוכן שייכים לטננט אחד (בית ספר או רשת). מורה לא רואה שיעור, קבוצה או עמדה של טננט אחר (נראה כאילו אינם). מורה שהוגדרו לו מעבדות רואה רק את העמדות שבהן. עריכות תוכן נשמרות לכל טננט בנפרד. תפקיד `content_admin` מאשר תוכן לטננט; בטננט שאין בו אחראי תוכן, כל מורה בו מאשר.

```bash
python3 tools/org.py add-tenant school-a "תיכון א"
python3 tools/org.py add-lab lab-a1 school-a "מעבדת פיזיקה 1"
python3 tools/org.py assign-station ST-MOT-VFD-1 lab-a1 "עמדה 1"
python3 tools/add_teacher.py noa "נועה" --tenant school-a --role content_admin
python3 tools/add_teacher.py rita "ריטה" --tenant school-a --labs lab-a1
```

חשבונות ועמדות קיימים שייכים לטננט `default`.

**הגדרות שרת:**

| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `DEMO` | `0` (ב־`run.sh`: `1`) | `1` פותח את מסכי המורה כשאין חשבונות, ואת טוקן הסימולטור |
| `COOKIE_SECURE` | `1` (ב־`run.sh`: `0`) | עוגיות רק ב־HTTPS |
| `TRUST_PROXY` | `0` | `1` מאחורי פרוקסי, כדי לזהות את כתובת הלקוח |
| `LESSON_HOURS` | `4` | אחרי כמה שעות שיעור נסגר מעצמו |
| `SECRET_KEY` | נוצר בקובץ | מפתח חתימה לעוגיות המורים |
| `ERROR_WEBHOOK_URL` | ריק | כתובת להתראה על שגיאות שרת |
| `APP_VERSION` | `dev` | הגרסה שמוצגת ב־`/api/health` |

**עמדה חיה:** לכל עמדה טוקן משלה, שנשמר רק כגיבוב:

```bash
python3 tools/add_station.py ST-MOT-VFD-1
```

**גיבוי:** `python3 tools/backup.py` יוצר עותק עקבי של מסד הנתונים גם כשהשרת רץ.

**הוספת מורה:**

```bash
python3 tools/add_teacher.py rita "ריטה"
```

הסיסמה נשאלת פעמיים ולא מוצגת. אותה פקודה מאפסת סיסמה למשתמש קיים. כל עוד לא הוגדר אף מורה, המערכת ב**מצב הדגמה**: מסכי המורה פתוחים לכל מי שמגיע, ופס צהוב אומר זאת. בשרת אמיתי מגדירים `SECRET_KEY` (מחרוזת אקראית ארוכה) ו־`COOKIE_SECURE=1` מאחורי HTTPS.

### הרצה מקומית

נדרשים Python 3.11 ומעלה ו־Node.js 20 ומעלה. פקודה אחת מתקינה, בונה ומפעילה:

```bash
./run.sh
```

אחר כך פותחים את http://localhost:8000. בדיקות: `cd apps/api && python3 -m pytest`.

| כתובת | מסך |
|---|---|
| `/teacher` | מסך מורה: פתיחת שיעור, כרטיסי עמדות, התראות, מחוון, יומן עמדה |
| `/teacher/login` | כניסת מורים |
| `/teacher/prep` | אשף הכנת שיעור |
| `/teacher/class` | כיתה לאורך זמן |
| `/teacher/students` | תלמידים: רשימת כיתה ופירוט לכל תלמיד |
| `/teacher/content` | תוכן: עריכה ואישור של התרגילים |
| `/join` | הצטרפות עמדה לשיעור עם קוד בן 6 ספרות |
| `/demo` | תרגול בלי שיעור |

הגדרות שרת להדגמה: `REPLAY_SPEED=4` מנגן את ההקלטה מהר יותר. `STUCK_SECONDS=60` מקצר את הזמן עד התראת ״תקוע״ (ברירת מחדל 300). `TEACHER_TOKEN=...` מאפשר לסקריפטים לגשת ל־API של המורה עם הכותרת `X-Teacher-Token`.

### Docker (מקומי)

```bash
docker build -t lab-mentor .
docker run -p 8000:8000 -v lab-state:/app/var -e DEMO=1 -e COOKIE_SECURE=0 lab-mentor
```

הקונטיינר רץ כמשתמש לא מורשה, והנתונים (מסד הנתונים, חשבונות, רשימות כיתה, גיבויים) נשמרים ב־volume שנקרא `lab-state`. הבנייה והרצה במצב ייצור נבדקו.

### פריסה בענן (חבילה 7)

על כל מכונה וירטואלית עם Docker (בכל ספק ענן). צריך שם דומיין שרשומת ה־A שלו מצביעה על המכונה, ושפורטים 80 ו־443 פתוחים.

```bash
cp deploy/env.example deploy/.env
```

בקובץ `deploy/.env` ממלאים לפחות `DOMAIN` ו־`SECRET_KEY` (הקובץ לא נכנס למאגר). אחר כך:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

```bash
docker compose -f deploy/docker-compose.yml exec app python /app/tools/add_teacher.py rita "ריטה"
```

מה עולה:
- **app:** השרת, במצב ייצור (`DEMO=0`, עוגיות רק ב־HTTPS, זיהוי כתובת הלקוח מאחורי הפרוקסי), עם בדיקת בריאות ב־`/api/health`.
- **https:** ‏Caddy, שמנפיק ומחדש לבד תעודת HTTPS לדומיין, ומוסיף כותרות אבטחה (HSTS, חסימת הטמעה במסגרת).
- **backup:** גיבוי כל לילה של מסד הנתונים וקבצי המצב לארכיון אחד, 14 אחרונים נשמרים. כדאי להעתיק את התיקייה מחוץ למכונה.

**שגיאות:** כל שגיאה בשרת נרשמת כשורת JSON עם מזהה בקשה (`X-Request-ID`), והמשתמש מקבל רק את המזהה. עם `ERROR_WEBHOOK_URL` נשלחת התראה (עד אחת לדקה), בלי טקסט של תלמידים.

**CI:** ‏`.github/workflows/ci.yml` מריץ בכל דחיפה את בדיקות השרת, בניית המסכים עם בדיקת טיפוסים, בדיקת דפדפן מקצה לקצה (`tests/e2e/smoke.cjs`), ובניית הקונטיינר עם בדיקת בריאות במצב ייצור.

### עמדה חיה (הדגמה עם סימולטור)

בקר העמדה שולח מסגרת `obs.v1` בכל שנייה אל `POST /api/edge/stations/<station>/obs`, עם הכותרת `X-Device-Token`. קוד המכשיר נקבע ב־`EDGE_TOKEN`. ברירת המחדל `dev-edge-token` מיועדת להדגמה בלבד. כדי לראות זאת בלי עמדה אמיתית מפעילים את השרת, ואז:

```bash
python3 tools/simulator/station_agent.py --run E04 --speed 2
```

אחר כך פותחים את http://localhost:8000/monitor. הסימולטור מנגן הקלטה כאילו היא מגיעה מהעמדה, ואם השרת לא זמין הוא שומר את המסגרות בתור ושולח אותן כשהשרת חוזר. היסטוריית הנתונים החיים נשמרת בזיכרון (10 דקות) ולא בדיסק.

### כלים

- `python3 tools/simulator/make_healthy.py` יוצר את ההרצות התקינות N01–N03 (`data/TLM_Rita_Normal_SIMULATED.csv`) לפי מפרט `TLM_Rita_02_Healthy.docx`, ובודק את כל ערכי הייחוס שבמפרט.
- `python3 tools/content_review.py` מעדכן את [docs/05-content-review.md](docs/05-content-review.md), דף קריא של תוכן התרגילים לבדיקת המורה.
